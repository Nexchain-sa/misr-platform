# منصة مصر متعددة القطاعات

منصة موحّدة (**Modular Monolith**) تخدم عدة قطاعات في مصر من خلال **نواة مشتركة** واحدة + **وحدات (modules)** لكل قطاع. القطاع الطبي مُنفَّذ بالكامل كقطاع رائد، وباقي القطاعات لها أساس جاهز للتوسّع بنفس النمط.

---

## 1) المعمارية

```
┌──────────────────────────────────────────────────────────────┐
│                    الواجهة (SPA عربي RTL)                     │
│              web/index.html + css + js/app.js                 │
└───────────────────────────┬──────────────────────────────────┘
                            │ REST /api  (JWT-token)
┌───────────────────────────┴──────────────────────────────────┐
│                  FastAPI  (backend/app.py)                    │
│   مصادقة · صلاحيات (RBAC) · سجل تدقيق · رفع ملفات · إشعارات    │
├──────────────────────────────────────────────────────────────┤
│  النواة المشتركة (Core)  ← تُبنى مرة واحدة وتخدم كل القطاعات   │
│  users · entities · official_documents · attachments ·        │
│  ratings · payments · notifications                           │
├──────────────────────────────────────────────────────────────┤
│  وحدة القطاع الطبي (مُنفَّذة بالكامل) — med_*                 │
│  specialties · doctors · patients · appointments ·            │
│  encounters · diagnoses · radiology · labs ·                  │
│  prescriptions(+items) · operations                           │
├──────────────────────────────────────────────────────────────┤
│  وحدات باقي القطاعات (أساس جاهز)                              │
│  con_* مقاولات · re_* عقاري · mkt_* تسويق · mob_* تنقل ·      │
│  log_* لوجستيات · agr_* زراعة · law_* محاماة                 │
└───────────────────────────┬──────────────────────────────────┘
                            │
                    SQLite (misr_platform.db)
```

**لماذا نواة مشتركة؟** لأن كل القطاعات تشترك في نفس اللبنات: مستخدمون وصلاحيات، كيانات/منشآت، أوراق رسمية وتصاريح، تقييمات، مدفوعات، إشعارات. نبنيها مرة واحدة ويستهلكها كل قطاع، بدلاً من تكرارها 9 مرات.

**الستاك:** FastAPI + SQLite + JWT/RBAC + واجهة Vanilla JS (بدون build) — نفس نمط مشاريعك السابقة (FLOWRIZ، Sama Style).

## 2) القطاع الطبي — السلسلة المتكاملة (مُنفَّذ بالكامل)

```
① حجز موعد        med_appointments
      ↓
② بدء الكشف        med_encounters   (علامات حيوية + فحص)
      ↓
③ التشخيص          med_diagnoses
      ↓
④ طلب أشعة         med_radiology_orders → قائمة مركز الأشعة → إدخال النتيجة
      ↓
⑤ طلب تحاليل       med_lab_orders       → قائمة المعمل      → إدخال النتيجة
      ↓
⑥ كتابة الروشتة    med_prescriptions    → تُرسَل أوتوماتيك لقائمة الصيدلية
                   (+ إشعار للصيدلي)     → الصيدلية تصرف الدواء
      ↓
⑦ إنهاء الكشف      يُحصّل سعر الكشف تلقائيًا (payments) + يُغلق الموعد
      ↓
⑧ السجل المرضي     خط زمني كامل لكل مريض (كل زياراته وتشخيصاته ونتائجه ورشتاته)
```

**مغطّى:** العيادات · الأطباء · التخصصات · الصيدليات · مراكز الأشعة · مراكز التحاليل · تقييم الأطباء (نجوم + متوسط) · المرضى والسجل المرضي · الحجوزات · التشخيصات · إرسال العلاج للصيدلية أوتوماتيك · الحالة المرضية · العمليات · الأوراق الرسمية للمنشآت (رفع ملفات فعلي).

## 3) مخطط قاعدة البيانات (ملخص الجداول)

### النواة المشتركة
| الجدول | الغرض |
|---|---|
| `users`, `sessions`, `audit_log` | المستخدمون والصلاحيات وسجل التدقيق |
| `entities` | كل المنشآت/الشركات لكل القطاعات (sector + kind) مع تقييم وتوثيق |
| `official_documents` | الأوراق الرسمية والتصاريح (رفع ملف + تواريخ إصدار/انتهاء) |
| `attachments` | مرفقات عامة |
| `ratings` | تقييمات (أطباء/صنايعية/منشآت) |
| `payments` | مدفوعات وارد/صادر لكل القطاعات |
| `notifications` | إشعارات المستخدمين |

### القطاع الطبي — `med_*`
`med_specialties`, `med_doctors`, `med_patients`, `med_appointments`, `med_encounters`, `med_diagnoses`, `med_radiology_orders`, `med_lab_orders`, `med_prescriptions`, `med_prescription_items`, `med_operations`.

### باقي القطاعات (أساس جاهز للتوسّع)
| القطاع | الجداول |
|---|---|
| المقاولات | `con_workers` (صنايعية بتخصص وتقييم), `con_projects` (بناء/تشطيب/ديكور/أثاث/هدم/نظافة) |
| التطوير العقاري | `re_projects`, `re_units` |
| التسويق العقاري/العام | `mkt_leads` (قمع بيع كامل) |
| التنقل | `mob_trips` |
| الشحن واللوجستيات | `log_shipments` (تتبّع) |
| الزراعة | `agr_farms` (مزارع/محاصيل/مواسم) |
| المحاماة | `law_cases` (قضايا/جلسات) |

## 4) التشغيل

```bash
pip install -r requirements.txt
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8020
```
ثم افتح: http://localhost:8020

## 5) خارطة التوسّع (القطاعات التالية)

كل قطاع جديد = نفس القالب الطبي: جداول الوحدة موجودة بالفعل، يتبقّى إضافة مسارات API + شاشات الواجهة. الترتيب المقترح:
1. **المقاولات** (الأكثر طلبًا: دليل صنايعية/مقاولين + أوامر شغل + تقييمات) — النواة تغطي الأوراق والتصاريح والتقييم بالفعل.
2. **التطوير + التسويق العقاري** (مترابطان: وحدات ← Leads ← بيع).
3. باقي القطاعات (تنقل، لوجستيات، زراعة، محاماة) بنفس النمط.
